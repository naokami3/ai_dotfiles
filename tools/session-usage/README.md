# session-usage

Claude Code のセッション記録（`~/.claude/projects/*/*.jsonl`）からトークン使用量とコストを集計するスクリプト。

`/cost` より細かく、「何にトークンを使ったか」「コンテキストがどう肥大したか」まで見えます。

## 使い方

```bash
python3 analyze.py                # 全セッションの要約
python3 analyze.py -p xrev        # プロジェクト名で絞り込み
python3 analyze.py -d             # コンテキスト推移と会話内容の構成比
python3 analyze.py --simulate     # 実装をSonnetに委譲した場合のコスト試算
```

依存パッケージはありません（標準ライブラリのみ）。

## 出力の見方

### 要約

```
プロジェクト                     session   ターン  sub        入力      出力   入:出        $
-Users-naokami-Works-xrev      ff13b58b     132    0  20,668,444  143,725   143:1    45.66
```

- **sub** — サブエージェント（サイドチェーン）の呼び出し回数。0 なら全て単一コンテキストで処理している
- **入:出** — 入力トークンと出力トークンの比。コーディングセッションでは 50:1〜400:1 になり、**コストの大半は出力ではなく入力**（毎ターン再送されるコンテキスト）が占める

### 詳細（`-d`）

コンテキストの四分位推移で、セッション中にどれだけ肥大したかが分かります。

```
第1四分位: 平均    78,549 tok
第4四分位: 平均   231,479 tok
```

後半ほど1ターンあたりの単価が上がるため、**セッションを適切に区切ることは、モデル選択と同等かそれ以上の削減手段**になります。

会話内容の構成比では、思考・ツール呼び出し・ツール実行結果の割合が出ます。実測では思考が46〜54%を占めており、effort 設定の見直しも独立した削減手段です。

### 試算（`--simulate`）

実装系ツール（Edit/Write/Bash 等）を使ったターンを Sonnet のサブエージェントに委譲した場合を試算します。委譲したターンが生んだコンテキスト増分は、以降メイン側に積まれないものとして計算します。

`claude-dev-orchestration-ja` プラグインを導入する価値があるかの目安に使えます。

**精度の限界:**

- サブエージェントの重複読み込み（Opus が読んだファイルを読み直す分）を計上していない → 分担側を**過小**評価
- 委譲対象を実装ツール使用ターンのみに限定 → 実際の実装フェーズはより広いため**過大**評価
- レビュー1パス分のコストは仮置き

誤差は±10ポイント程度です。傾向を見る用途に留め、絶対額の根拠には使わないこと。

## 単価について

`PRICE` 定数に単価をハードコードしています。公表価格の変更に追従していない可能性があるため、金額を根拠に判断する場合は最新の価格表と突き合わせてください。サブスクリプション利用時は、金額ではなく利用上限の消費ペースとして読み替えます。

## 品質の検証について

コスト削減と引き換えに出力品質が落ちていないかは、このスクリプトでは測れません。別途、以下の客観指標で比較します。

1. テスト初回通過率 — 修正ループに入らず完了したか
2. 修正ループの周回数
3. ユーザーの差し戻し回数
4. 差分の大きさ（`git diff --stat`）— 必要以上に触っていないか
5. 受け入れ基準の充足数

**手順:** 同一の開始コミットから同じタスクを2アーム実行し（`git worktree` で分離）、アームの実行順を交互に入れ替えて順序効果を消します。主観評価が必要な部分は、どちらのアームか伏せて差分だけを独立したレビューエージェントに渡します。

最小構成として、実タスク1件を worktree で2回やるだけでも、テスト初回通過と差し戻し回数の差は見えます。
