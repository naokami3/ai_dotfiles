# system-inventory-ja

1つのシステムのコード全体から、**漏れと捏造を機械的に抑えた機能一覧**を作る Claude Code プラグイン。
成果物は Excel（.xlsx）・HTML・Markdown の3形式です。

普段の開発では影響範囲だけを読めば足ります。しかし、システムの統合や移行の前には全体像を正確に
把握する必要があります。そこで全コードを1つのエージェントに読ませると、コンテキストが溢れて詳細が落ち、
名前からの推測で「ありそうな機能」を書いてしまいます。このプラグインは、その失敗を仕組みで防ぎます。

対象は1システムです。複数システムの比較・対応付けは扱いません。

## 構成

| 種別 | 名前 | 役割 |
|---|---|---|
| スキル | `build-feature-inventory` | オーケストレーター。進行・判断・グループ分け |
| エージェント | `inventory-extractor`（Sonnet） | 1スライス（数千行）を読み、根拠付きで機能を抽出 |
| エージェント | `inventory-verifier`（Sonnet） | 集約済みの機能をコードと突合する独立検証 |
| スクリプト | `scripts/*.py` | 分母作成・分割・引用照合・網羅率・集約・出力 |
| 検出器 | `detectors/*.yaml` | 入口（API・画面・ジョブ・CLI・テーブル）を列挙する正規表現 |

## 仕組み

```
Phase 0 偵察と見積もり : ファイル分母と入口分母をスクリプトで作り、スライス数と概算トークンを提示 → 承認
Phase 1 パイロット     : 2〜3スライスで実測し、見積もりを補正
Phase 2 抽出（並列）   : スライスごとにサブエージェントが読み、根拠（ファイル:行＋引用）付きで JSON に書く
Phase 3 機械検証       : 引用がその行に実在するか・全入口が対応付いたか・全範囲を読んだかを照合。不合格は修正モードで差し戻し
Phase 4 集約           : 1行ダイジェストからグループ分け。入口・データ・根拠はスクリプトが引き継ぐ
Phase 5 独立検証       : リスクの高い機能から別エージェントがサンプリングして突合
Phase 6 出力           : features.json（正典）から xlsx / html / md を生成
```

### ハルシネーションと漏れの抑え方

| 仕組み | 機械で保証できる範囲 |
|---|---|
| `git ls-files` 由来のファイル一覧と検出器で列挙した入口一覧を分母にし、網羅率を数値で出す | 分母内の網羅。除外したファイル内の入口候補は警告する |
| スライスごとに新しいサブエージェントが読む。オーケストレーターはコードを読まない | — |
| スクリプトが無作為に選んだ区間から1行ずつ引用させる（読了確認） | 指定区間の実在行を答えたこと |
| すべての主張に `ファイル:行` と引用を付けさせ、その行に実在するか照合する | 引用文字列の実在 |
| 利用者・制約（〜のみ・〜できない）は1件ずつ根拠行を必須にする | 根拠行が示されていること |
| 集約で書けるのは名前・グループ分け・利用者表記の写像だけ。単独の機能は局所要約をそのまま使う | 入口・データ・根拠・制約・確信度は改変不可 |
| 別エージェントがリスク順の抜き取りで、機能と「対象外にした入口」をコードと突合する | 抜き取りの範囲のみ（統計的） |

**意味の正しさは機械では保証できません。** そのため、独立検証の結果（誤り率）と確信度・要確認事項を
成果物に必ず残します。

ID（スライス・機能）は内容から決まるので、再実行や再集約をしても、検証結果や参照が別の機能に
付け替わることはありません。

### トークンの節約

- 決定的な処理はすべてスクリプトが行い、標準出力は要約だけを返す
- 生成物・ロックファイル・minify 済み・巨大データ・重複ファイルを除外する
- テストはアウトライン読み（テスト名・定義行のみ）にする
- パイロットで1行あたりのトークンを実測してから本実行する
- 不合格はエラー一覧だけを渡して直させる
- 内容が変わっていないスライスは抽出結果を引き継ぐ（コード更新後や検出器修正後も差分だけ再実行）
- 独立検証はリスク順のサンプリングにする

## 成果物

| ファイル | 内容 |
|---|---|
| `feature-inventory.xlsx` | シート: 概要 / 機能一覧 / 入口一覧 / 要確認（オートフィルタ・見出し固定） |
| `feature-inventory.html` | 1ファイル完結。検索、ドメイン・確信度・入口有無での絞り込み、行クリックで詳細表示 |
| `feature-inventory.md` | 差分確認・エージェント向け |
| `features.json` | 正典。上の3つはここから生成する |

## 対応スタック

ファイル分母・スライス分割・検証は言語に依存しません。入口の列挙は検出器 YAML によります。

- 同梱: FastAPI、Next.js（App / Pages Router）、Python のジョブ・CLI・ORM、SQL・Prisma・Drizzle 等のデータ定義、
  Express 系・NestJS・Spring・ASP.NET・Go・Rails・Laravel のルート、ファイルベースルーティング
  （TanStack Router / Remix / SvelteKit / Nuxt）、cron 類
- 同梱で拾えないスタックでは、Phase 0 で検出器 YAML を追加します（`references/detectors.md`）

## 必要なもの

- Python 3.9 以上
- PyYAML（`pip install pyyaml`。検出器の読み込みにのみ使用）
