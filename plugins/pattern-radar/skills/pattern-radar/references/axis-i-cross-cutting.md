# 軸I: 横断関心

対象シグナル: 全リクエストでログ・認証・計測を通したい / 同じ before_action が3コントローラ以上にある /
Concern が肥大している / 前後処理を本体に触らず足したい

このファイルの項目はすべてスタブ（発火条件のみ）。実装例は必要になった時点で追記する。

## Middleware・Interceptor

発火条件: 全リクエスト（または全ジョブ）で同じ前後処理が必要 /
同じ `before_action` が3コントローラ以上に複製されている。
適用しない条件: 対象が1コントローラのみ。

## Decorator（構造）

発火条件: 既存クラスのインタフェースを変えずに責務を1つ足したい要求が2回以上出ている /
継承で表現すると組み合わせ爆発する（機能の掛け合わせが3通り以上）。
適用しない条件: 追加する責務が1つで、本体を直接変更できる。

## Concern・Mixin

発火条件: 同じメソッド群が2モデル以上に複製されている、かつ状態を持たない /
`include` するだけで意味が通る単位に切り出せる。
適用しない条件: 切り出す単位に状態や依存があり、実体はコラボレータ（別クラス）である。
Concern が200行を超えている場合は、Concern ではなく別オブジェクトを検討する。
