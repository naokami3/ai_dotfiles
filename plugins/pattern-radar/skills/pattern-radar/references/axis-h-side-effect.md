# 軸H: 副作用と通知

対象シグナル: after_commit / after_save が育つ / 保存したらメール・通知・外部連携が走る /
通知の送信漏れ・二重送信 / 処理の順序に依存した副作用 / 誰が何を購読しているか追えない

detect.rb の該当 signal: `callback_block_lines`

このファイルの項目はすべてスタブ（発火条件のみ）。実装例は必要になった時点で追記する。

## Observer・Pub-Sub

発火条件: 1つの出来事に対する後続処理が3つ以上あり、今後も増える見込みがある /
`after_commit` のブロックが5行以上あり、無関係な処理が同居している。
適用しない条件: 後続処理が1つで、呼び出し元から直接呼べば済む。

## Outbox

発火条件: DB更新と外部送信（メール、Webhook、キュー投入）が同じ手続きにあり、
片方だけ成功する事故が起きうる / 送信漏れの調査要求が出ている。
適用しない条件: 送信失敗が業務的に許容され、再送も不要。

## Mediator

発火条件: 3つ以上のオブジェクトが相互に直接呼び合っており、依存が循環している。
適用しない条件: 依存が一方向。

## Event Sourcing

発火条件: 状態の履歴（誰がいつ何を変えたか）が業務要件で、現在値だけでは監査に足りない /
過去時点の状態を再現する要求がある。
適用しない条件: 監査ログのテーブル追加で足りる。
