# 軸B: 生成の複雑化

対象シグナル: 初期化が長い / 引数が多いコンストラクタ / 生成時の条件分岐 /
`new` する場所が散る / テストデータの用意が毎回違う / 依存が直接 `new` されていて差し替えられない

このファイルの項目はすべてスタブ（発火条件のみ）。実装例は必要になった時点で追記する。

## Factory Method

発火条件: 生成する具象クラスを条件で選ぶ分岐が2箇所以上にある /
生成の直後に必ず同じ初期化手続きが続く。
適用しない条件: 具象が1つ、または `new` するだけで完成する。

## Builder

発火条件: コンストラクタの引数が5つ以上、または任意引数が3つ以上ある /
生成手順に順序依存があり、途中状態のまま使うと壊れる。
適用しない条件: キーワード引数と既定値で十分表現できる。

## Dependency Injection

発火条件: クラス内部で外部依存を直接 `new` / クラスメソッド呼び出ししており、テストで差し替えられない /
同じ依存を使う箇所が3箇所以上ある。
適用しない条件: 依存が標準ライブラリなど差し替え不要なもの。

## Fixture Builder（テストデータビルダー）

発火条件: 同じモデルのテストデータ生成が3箇所以上で重複している /
必須の関連が2つ以上あり、テストごとに組み立て方が違う。
適用しない条件: FactoryBot などの既存機構で足りており、重複が無い。
