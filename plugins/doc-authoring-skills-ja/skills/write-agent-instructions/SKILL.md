# エージェント指示ファイル作成・更新ガイド

## 関連スキルの使い分け

| 対象 | スキル |
|---|---|
| AGENTS.md / CLAUDE.md 等のエージェント指示ファイル | `write-agent-instructions`（本スキル） |
| 技術的な意思決定の記録 | `write-adr` |
| architecture.md / roadmap.md 等の docs/ 配下 | `write-project-docs` |
| 人間向け HTML 資料（概観・詳細仕様・図） | `write-html-docs` |
| 作成・更新後の検証 | `review-docs` |

## どのファイルに書くか

**AGENTS.md をプロジェクトの正とする。** Codex、Cursor、GitHub Copilot、Gemini CLI、Zed、Aider など多数のエージェントがこのファイルを直接読む。

Claude Code は AGENTS.md を読まないため、ブリッジを1つ置く:

```markdown
<!-- CLAUDE.md -->
@AGENTS.md

## Claude Code 固有

（Claude Code だけに効かせたい指示があればここに書く。無ければこのセクションごと不要）
```

Claude 固有の追記が不要ならシンボリックリンクでもよい:

```bash
ln -s AGENTS.md CLAUDE.md
```

Windows でのシンボリックリンク作成は管理者権限または開発者モードが必要なため、チームに Windows 環境が含まれる場合は `@AGENTS.md` インポート方式を選ぶ。

**同じ内容を2ファイルに複製しない。** 複製は必ず片方だけ更新されて食い違い、エージェントがどちらを採用するか不定になる。

## 構成（この順序で記述する）

1. **プロジェクト概要** — 1-2文。技術スタックを含む
2. **コマンド** — ビルド、テスト、リント、起動コマンド。エージェントが推測できないものを優先
3. **コーディング規約** — デフォルトと異なるルールのみ。リンター/フォーマッターの仕事は書かない
4. **絶対に守るルール** — 違反すると壊れる制約。番号付きリストで明確に
5. **既知の落とし穴** — コードを読んだだけでは分からない非自明な問題
6. **関連ドキュメント** — docs/、CONTRIBUTING.md 等へのリンク

## 書くべきもの

- エージェントが推測できないプロジェクト固有の情報
- 違反すると即座にバグになるルール
- 過去にハマった落とし穴（DLL 競合、ライセンス制約等）
- ビルド/テスト/デプロイのコマンド
- 同じ訂正を2回以上会話に打ち込んだ内容

## 書くべきでないもの

- コードを読めば分かること（ファイル構造、関数一覧、依存パッケージ一覧）
- リンター/フォーマッターが検出するスタイルルール
- モデルが学習済みの一般知識（フレームワークの標準的な使い方等）
- 長い説明やチュートリアル（docs/ に分離する）
- 差別化ポイントやマーケティング文言（README 向き）
- 自明なプラクティス（「クリーンコードを書け」等）

## 分量と、はみ出したときの逃がし先

**200行以内を目標とする。** 指示ファイルは毎セッション先頭で全文読み込まれるため、長いほどトークンを恒常的に消費し、かつ個々の指示の遵守率が下がる。

「これを削除したらエージェントは間違いを犯すか？」— No なら削除する。

200行に収まらない場合、削る前に**置き場所を変える**:

| はみ出した内容 | 逃がし先 |
|---|---|
| 特定ディレクトリ・ファイル種別にだけ効くルール | パススコープのルールファイル（Claude Code なら `.claude/rules/*.md` の `paths` フロントマター、Cursor なら `.cursor/rules/`、Copilot なら `.github/copilot-instructions.md` 系） |
| 手順に育ったセクション（複数ステップの作業） | スキル（`SKILL.md`）。呼ばれたときだけ読み込まれる |
| モノレポの特定パッケージ固有の内容 | そのディレクトリに置いた AGENTS.md。エージェントは編集対象に最も近いものを採用する |
| 参照用の長い資料 | docs/ に置き、指示ファイルからはリンクで参照する |

**注意: `@path` インポートはコンテキストを削減しない。** インポートされたファイルは起動時に展開されて読み込まれる。分量削減が目的なら、インポートではなくパススコープのルールかスキルへ移す。

## ルール記述のパターン

```markdown
## 絶対に守るルール

1. **何をしてはいけないか** — なぜ（1行で）
2. **何をすべきか** — どのファイル/モジュールで
```

- **理由を1行で添える。** 理由があるルールは、想定外のケースにも一般化して適用される。理由のない「MUST」は、条件が少しずれた瞬間に守られなくなる
- 具体的なファイルパスを含める
- 禁止ルールは「〜してはならない」、必須ルールは「〜で定義する」
- 検証できる具体性で書く（「適切にフォーマットする」ではなく「インデントは半角スペース2つ」）

## 落とし穴の記述パターン

```markdown
## 既知の落とし穴

- **問題の名前**: 対処法。詳細は [リンク]
```

- 名前を太字にして一覧性を確保
- 対処法を1行で書き、詳細は ADR やドキュメントにリンク

## 矛盾のチェック

複数の指示ファイル（ルート AGENTS.md、サブディレクトリの AGENTS.md、ルールファイル、ユーザー個人の設定）が矛盾すると、エージェントはどちらか一方を任意に選ぶ。更新時は既存の全指示ファイルを読み、矛盾する記述がないか確認する。

## 作成手順

1. 既存の指示ファイル（AGENTS.md, CLAUDE.md, `.cursor/rules/`, `.github/copilot-instructions.md` 等）を全て確認する
2. AGENTS.md を作成・更新する
3. Claude Code 用のブリッジ（`@AGENTS.md` インポートまたはシンボリックリンク）が存在するか確認し、無ければ作成する
4. 200行を超えていないか確認し、超えていれば上表に従って逃がす
5. **`review-docs` の基準で検証する。** must-fix 相当の指摘があれば修正してから完了報告する
