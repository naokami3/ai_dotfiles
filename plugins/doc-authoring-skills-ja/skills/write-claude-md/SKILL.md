# CLAUDE.md 作成・更新ガイド

プロジェクトの CLAUDE.md を Anthropic のベストプラクティスに従って作成する。

## 構成（この順序で記述する）

1. **プロジェクト概要** — 1-2文。技術スタックを含む
2. **コマンド** — ビルド、テスト、リント、起動コマンド。Claude が推測できないものを優先
3. **コーディング規約** — デフォルトと異なるルールのみ。リンター/フォーマッターの仕事は書かない
4. **絶対に守るルール** — 違反すると壊れる制約。番号付きリストで明確に
5. **既知の落とし穴** — コードを読んだだけでは分からない非自明な問題
6. **関連ドキュメント** — docs/, CONTRIBUTING.md 等へのリンク

## 書くべきもの

- Claude が推測できないプロジェクト固有の情報
- 違反すると即座にバグになるルール
- 過去にハマった落とし穴（DLL 競合、ライセンス制約等）
- ビルド/テスト/デプロイのコマンド

## 書くべきでないもの

- コードを読めば分かること（ファイル構造、関数一覧）
- リンター/フォーマッターが検出するスタイルルール
- 長い説明やチュートリアル（docs/ に分離する）
- 差別化ポイントやマーケティング文言（README 向き）
- 自明なプラクティス（「クリーンコードを書け」等）

## 品質基準

- **60行以下** が理想。200行を超えない。300行超は効果が著しく低下
- 「これを削除したら Claude は間違いを犯すか？」— Noなら削除
- 毎月見直して不要な指示を削除する
- docs/ に詳細を置き、CLAUDE.md はリンクだけにする

## ルール記述のパターン

```markdown
## 絶対に守るルール

1. **何をしてはいけないか** — なぜ（1行で）
2. **何をすべきか** — どのファイル/モジュールで
```

- 理由を1行で添える（将来の開発者が判断できるように）
- 具体的なファイルパスを含める
- 禁止ルールは「〜してはならない」、必須ルールは「〜で定義する」

## 落とし穴の記述パターン

```markdown
## 既知の落とし穴

- **問題の名前**: 対処法。詳細は [リンク]
```

- 名前を太字にして一覧性を確保
- 対処法を1行で書き、詳細は ADR やドキュメントにリンク
