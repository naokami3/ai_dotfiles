# AI Slop Review (Japanese)

日本語文章からAI生成特有のパターン（スロップ）を検出し、**自然な日本語に直すための修正方向**を示す構造化レポートを出力する。

## このskillの責任範囲

- **担当する**: AI生成文章に特徴的な語彙・文体・構造・コンテンツ・表記パターンの検出、自然な日本語への修正方向の提示
- **担当しない**: 特定の執筆者のスタイル寄せ、一人称や文体（常体/敬体）の指定、個人的な語彙の好み

スタイル寄せは別のskillや別ターンで行う。このskillは「誰が読んでもAIっぽいとわかる特徴」を潰すことだけに集中する。

## 報告の共通基準（最重要）

**パターンに一致しただけでは報告しない。** 人間も「一方で」「まさに」「〜ではなく〜だ」を普通に使う。
AIの特徴は個々の表現ではなく、**それを毎回・機械的にやること**にある。

次の2つを**同時に**説明できる場合だけ報告する。

1. **読者にとっての具体的な損失があること**（下表のいずれか）
2. **そのパターンの反証質問に耐えたこと**（各パターンの「棄却例」に該当しないこと）

### 損失の判定

| 損失 | 判定手順 |
|---|---|
| **重複** | 寄与しない かつ 同じ情報が文書内の他箇所にある |
| **空洞** | 寄与しない かつ 重複元もない（そこにしかないのに中身がない） |
| **冗長** | 寄与する が、意味・事実・必要な強調を保ったまま短くできる |
| **偽の対比** | 対比の両側が同じ内容の言い換えになっている |
| **文脈不適合** | 語や構文が前後の文体・専門度から浮いている |

判定は次の順で行う。

```
この箇所は読者の理解・判断・再現可能性に寄与するか？
├─ 寄与しない
│    └─ 同じ情報が他箇所にあるか？
│         ├─ ある   → 重複
│         └─ ない   → 空洞
└─ 寄与する
     └─ 意味・事実・必要な強調を保ったまま短くできるか？
          ├─ できる → 冗長
          └─ できない → 棄却（報告しない）
```

**文種による免除は設けない。** 「推論だから」「例示だから」という理由で自動的に棄却しない。
一般論への言い換え、循環した解釈、役に立たない例示は、推論や例示の形をしていても報告する。

### 報告しないもの

- 損失を具体的に説明できないもの（「AIっぽい」だけが理由のもの）
- 各パターンの棄却例に該当するもの
- 迷ったもの。**確信が持てなければ報告しない。** 誤検出を1件減らす方が、取りこぼしを1件減らすより価値が高い

## 処理フロー

1. **入力受け取り**: レビュー対象のテキスト（markdown可）。行番号の付け方は下記
2. **候補列挙**: 各レイヤーで該当箇所を洗い出す（この段階では広く拾う）
3. **反証**: 候補ごとに棄却例と照合し、損失を説明できるか確かめる。耐えたものだけ残す
4. **重度判定**: 生き残った指摘に🔴重度 / 🟡中度 / 🟢軽度を付与（表記所見を除く）
5. **構造化レポート出力**: 下記フォーマットで出力

ステップ2で挙げた候補をそのまま報告してはいけない。**3を必ず通す。**

## 行番号の付け方

出力の `[L{行番号}]` は次の規則で数える。

- **ファイルを渡された場合**: そのファイルの1行目を 1 とする
- **本文を直接貼られた場合**: 貼られたテキストの1行目を 1 とする
- 先頭・末尾の空行も**数える**（削らない）
- コードブロックの中も**行数には数える**（検出対象からは外す）
- 表示上の折り返しは無視し、**論理行**で数える
- 複数ファイルを渡された場合はファイルごとに独立して数え、ファイル名を併記する

## 検出レイヤー

### Layer 1: 語彙レベル
定型句・キラーワード・過剰カタカナ語・漢語過剰・否定的対比。
詳細と棄却例は`references/patterns-lexical.md`を参照。

### Layer 2: 文体レベル
- 文末表現の連続（3文以上連続で同じ語尾）
- 抽象名詞による体言止め
- 接続詞の過剰（「また」「さらに」「しかしながら」の多用）
- 文長のばらつき欠如（burstiness低下）

### Layer 3: 構造レベル
- 段落長の均一性
- 見出し宣言の重複（見出しの内容を本文冒頭で言い直す）
- 鋳型構造（「概要→メリット→デメリット→まとめ」の型）
- 段落末の「きれいに閉じる」癖
- 三段上昇（3項目の最後が前2つの壮大な言い換えになる）
- 一点の希釈（1つの主張を言い換えて反復し、深さを演出する）

### Layer 4: コンテンツレベル
- 具体性の欠如（数値・固有名詞・コードの不足）
- 筆者性の欠落（個人的試行錯誤・失敗談・違和感の不在）
- 平均回帰（「革新的」「強力な」など評価語で中身を代替）
- 結論の空洞（「結論から言うと」の後が抽象的一般論）
- 例外の不在（トレードオフ・反例・うまくいかなかった条件が一切書かれていない）

### Layer 5: 事実性チェック（最重要）

Layer 4で「具体性を出せ」と指示すると、書き直しエージェントが辻褄合わせで
数値・期間・経験を**捏造するリスクがある**。捏造された具体は一見AI臭を
消すが、実際には記事の信頼性を根本から損なう。捏造の検出と警告を行う。

Layer 2〜5の詳細は`references/patterns-structural.md`を参照。

### 表記所見（重度判定の対象外）

見出しのコロン、太字の過剰、絵文字見出し、箇条書きの均一性、Markdown記号の残骸など。
詳細と棄却例は`references/patterns-notation.md`を参照。

日本語圏で「一瞬でAIと分かる」と言われるのはこの層だが、**内容の質とは独立している**。
表記所見がゼロでも中身が空洞なら記事は良くならないので、重度判定にも総合所感にも算入しない。

**例外**: Markdown記号の残骸（`**` が本文に残っている等）は表示が壊れるため最優先で直す。

## 重度判定基準

- **🔴 重度**: 内容が空洞化しているパターン。削除または全面書き直しが必要
  - 例: 評価語だけで具体が無い、定型句で中身が無い、ヘッジで断定を避けている
- **🟡 中度**: 目立つAIパターンだが、修正すれば活かせる
  - 例: 定型的な接続詞、単調な文末、見出し宣言の重複
- **🟢 軽度**: 軽微なAI臭。余裕があれば直す
  - 例: カタカナ語の置き換え、1〜2箇所の文末単調

## 出力フォーマット

以下のフォーマットを厳守する。別エージェントまたは執筆者が機械的に消費できるよう構造を一定に保つ。

```markdown
# AI臭レビュー結果

## 📊 サマリ
- 🔴 重度: N件
- 🟡 中度: N件
- 🟢 軽度: N件
- 📐 構造的所見: N件
- 🖋 表記所見: N件
- ⚠️ 事実性要確認: N件

全体的な所感を1〜2行で記述（例: 「典型的な解説記事テンプレートに沿った文章。筆者性が薄く、Layer 4の問題が多い」）
※表記所見は所感に算入しない。

## ⚠️ 事実性要確認

書き直し前に執筆者に確認すべき記述。具体的すぎる数値・経験・期間などが
含まれており、事実確認が取れていなければ捏造リスクがある。

### [L{行番号}] 「該当箇所の引用」
- **確認事項**: 何を確認すべきか（例: この処理時間は実測値か？）
- **対応方針**: 事実なら残す / 不確実なら一般化する / 創作なら削除する

## 🔴 重度

### [L{行番号}] 「該当箇所の引用（長い場合は前後略）」
- **問題**: 何が問題か（パターン名で具体的に指摘）
- **損失**: 重複 / 空洞 / 冗長 / 偽の対比 / 文脈不適合 のどれか。読者が何を失うか1行で
- **修正方向**: どう直すか（自然な日本語にする方向を指示）

（複数あれば同じ形式で繰り返す）

## 🟡 中度

### [L{行番号}] 「該当箇所の引用」
- **問題**: ...
- **損失**: ...
- **修正方向**: ...

## 🟢 軽度

### [L{行番号}] 「該当箇所」
- **問題**: ...
- **損失**: ...
- **修正方向**: ...

## 📐 構造的所見

- **段落長の均一性**: 観察（例: 全9段落がすべて3〜4文で均一）
  - 修正方向: ...
- **接続詞頻度**: 観察（例: 「また」5回、「さらに」3回）
  - 修正方向: ...
- **見出し構造**: 観察（例: 「概要→メリット→デメリット→まとめ」の鋳型）
  - 修正方向: ...

## 🖋 表記所見

内容の質とは独立した、見た目のAI臭。重度判定の対象外。

### [L{行番号}] 「該当箇所」
- **パターン**: N-1 コロン多用 / N-2 太字過剰 など
- **修正方向**: ...

## 🎯 書き直し優先順位

1. **まず⚠️事実性要確認の項目を執筆者に確認**（確認なしに具体化しない）
2. Markdown記号の残骸があれば先に直す（表示が壊れるため）
3. 🔴重度の{件数}件を潰す（中身の空洞化を解消）
4. 📐構造的所見（段落・見出し・接続詞の改変）
5. 🟡中度・🟢軽度
6. 最後に🖋表記所見

## 📎 修正時の前提

このレビューはAI臭を除去して**自然な日本語にする**ことだけが目的。
特定の執筆者スタイル（一人称、常体/敬体、語彙の好み）への寄せは
別工程で行う。まず自然な日本語に直してから、スタイル寄せに進むこと。

具体化の指示については、**事実として確認できる情報のみ使うこと**。
不明な場合は具体化せず、執筆者に確認を求めるか、一般的な記述にとどめる。
```

## 重要原則

- **パターン名で具体的に指摘する**: 「AIっぽい」とは書かない。「Layer 2 / 文末単調」「Layer 4 / 筆者性の欠落」のように根拠を示す
- **損失を必ず書く**: 読者が何を失うかを説明できない指摘は出さない
- **問題箇所の引用を省略しない**: 書き直し時に該当箇所を特定できるように
- **優先順位をつける**: すべて列挙するのではなく、影響度順に並べる
- **修正方向は指示形で書く**: 「〜してはどうか」ではなく「〜する」「〜に置き換える」
- **スタイルには踏み込まない**: 「一人称を自分にせよ」「常体にせよ」のような指示は出さない。あくまで「自然な日本語」を目標に指示する
- **過剰検出を避ける**: 軽度の問題を大量に出すより、重度を正確に指摘する方が価値が高い。**迷ったら報告しない**
- **事実性を最優先**: 具体化指示には必ず「事実に基づくもののみ」を添える

## 自己チェック

レビュー出力後、以下を確認：

1. すべての指摘に行番号または引用がついているか
2. **すべての指摘に「損失」が書かれているか**。書けなかった指摘は削除する
3. **各指摘は、そのパターンの棄却例と照合したか**
4. 問題と修正方向が1対1で対応しているか
5. 重度判定が妥当か（全部🔴になっていないか、全部🟢になっていないか）
6. 表記所見を重度判定や総合所感に混ぜていないか
7. 特定の執筆者スタイルに踏み込んでいないか（一人称や常体/敬体を指定していないか）
8. Layer 4で具体化を指示している箇所に「事実に基づくもののみ」の注記があるか

問題があれば修正して出力する。
