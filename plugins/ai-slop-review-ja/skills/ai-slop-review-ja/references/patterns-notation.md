# 表記・書式パターン（表記所見）

見た目でAI生成と分かってしまうパターン。日本語圏の読者が「一瞬で分かる」と言うのは
たいていこの層である。内容の質とは独立しているので、**重度判定とは別枠**で報告する。

**重要**: この層がゼロでも、内容が空洞なら記事は良くならない。
表記だけ直して「AI臭が消えた」と判断しない。

---

## N-1. 見出し・文中のコロン「：」

日本語では文末にコロンを置く習慣が薄い。英語ライティングの直輸入で、最も指摘されやすい。

### 検出例
```
## 導入手順：3つのステップ
ポイントは以下のとおりです：
注意点：この設定は本番では使えない
```

### 修正方向
- 見出しのコロンは削って体言止めか、全角スペース・読点に置き換える
- 「以下のとおりです：」→「以下のとおり。」または削除して箇条書きに直結させる

### 棄却例（報告しない）
- 時刻表記（`13:00`）、比率（`2:1`）、コード内、URL 内
- 用語の定義列（`API: Application Programming Interface`）のように対訳・定義として機能している場合

---

## N-2. 太字の過剰・行頭太字の箇条書き

AIは強調すべきでない語まで太字にする。特に箇条書きの行頭を機械的に太字化する。

### 検出例
```
- **導入コスト**: 低い
- **学習コスト**: 中程度
- **運用コスト**: 高い
```
全項目が同じ形。これが3項目以上続いたらフラグ。

### 修正方向
- 行頭太字を普通の文に開く。「導入コストは低いが、運用コストは高い。」
- 太字は記事全体で2〜3箇所に絞る。どこを強調したいかが決まっていない太字は削る

### 棄却例
- 用語の初出定義
- 警告・禁止事項（本当に見落としてほしくない箇所）
- 対比表の見出し列

---

## N-3. Markdown記号の残骸

AIの出力をコピペした痕跡。`**` や `#` がそのまま本文に残っている。

### 検出例
```
これは**重要な点です。
### 次のステップ について
```

### 修正方向
- 記号を削除するか、正しい記法に直す
- **これは最優先で直す。** 読めない・崩れて表示されるのは内容以前の問題

### 棄却例
- コードブロック内、インラインコード内の記号

---

## N-4. 絵文字見出し・装飾記号

### 検出例
```
## 🚀 はじめに
## 💡 ポイント
✅ 設定完了
⚠️ 注意
```

見出しの先頭に絵文字が**規則的に**付いている場合にフラグ。

### 修正方向
- 削除する。見出しの文言で役割が分かるなら絵文字は要らない
- 使うなら不規則に、本当に目立たせたい1〜2箇所だけに

### 棄却例
- 記事全体のトーンとして一貫して使っている（本人のスタイル）
- 状態表示として意味を持つ場合（✅完了 / ❌失敗 の対比表など）

---

## N-5. 箇条書き項目の均一性（説明書感）

各項目の文字数と語尾が揃いすぎている。人間が書くと長さは自然にばらつく。

### 検出シグナル
- 全項目が同じ語尾（「〜こと。」「〜する。」「〜できます。」）
- 全項目の文字数がほぼ同じ
- 全項目が同じ品詞で始まる

### 修正方向
- 重要な項目だけ長く書き、そうでない項目は短くする
- 1項目だけ体言止めにする、1項目だけ2文にする
- そもそも箇条書きにする必要があるか見直す（散文で書ける内容を箇条書きに逃がしていないか）

### 棄却例
- 手順書・チェックリスト（揃っている方が読みやすい種類の文書）
- API のパラメータ一覧など、構造が本質的に対称なもの

---

## N-6. 箇条書き・表への過剰依存

散文で書くべき内容を箇条書きや表に逃がしている。

### 検出シグナル
- 記事全体で地の文より箇条書きの行数が多い
- 見出し直後がいきなり箇条書きで、つなぎの説明がない
- 2項目しかないのに表にしている

### 修正方向
- 因果関係や判断の理由は散文で書く。箇条書きは並列な事実の列挙に限る
- 表は3列以上・3行以上で初めて価値が出る。それ未満は文で書く

### 棄却例
- 比較記事、リファレンス、手順書（構造化が目的の文書）

---

## N-7. em dash / 全角ダッシュの挿入句

英語の `—` の直輸入。日本語では読点や括弧で足りることが多い。

### 検出例
```
この設定は—本番環境では特に—慎重に扱う必要がある。
```

### 修正方向
- 読点か括弧に置き換える。「この設定は、本番環境では特に、慎重に扱う」
- 多くの場合は挿入句ごと削れる

### 棄却例
- 会話文の中断、引用の省略記号として機能している場合
- 記事全体で一貫したスタイルとして使っている場合

---

## 検出時の注意

- **1〜2箇所の出現では報告しない。** 規則的に繰り返されている場合だけ報告する
  （人間も見出しにコロンを使うことはある。AIの特徴は「毎回そうすること」）
- 表記所見は **🔴🟡🟢 の重度判定を付けない**。総合判定にも算入しない
- ただし **N-3（Markdown残骸）だけは例外**。表示が壊れるので最優先で直す
- コードブロック内・引用内は全項目とも対象外
