# 語彙パターン詳細（Layer 1）

AI生成文章に頻出する日本語の定型句・キラーワード・過剰カタカナ語のリスト。検出時はここを参照する。

## カテゴリ

1. 中身のない強調
2. 定型的な句
3. ヘッジ表現
4. 過剰なカタカナ語
5. 段落末の「きれいに閉じる」系
6. 導入の定型
7. 接続の常套句

---

## 1. 中身のない強調

内容を具体的に語る代わりに評価語で埋めるパターン。Layer 4「平均回帰」にも関連。

- 包括的な
- 多面的な / 多角的な
- 革新的な / 画期的な
- 最適な / 最適化された
- 効率的な / 効率化
- 強力な
- 優れた
- 高度な
- 重要な役割を果たす
- 非常に重要
- きわめて重要
- 多くのメリット
- さまざまな利点
- 幅広い用途
- 劇的に改善
- 飛躍的に向上
- 大幅に
- 圧倒的な

**修正方向**: 何がどう「革新的」「強力」なのか具体化する。数値・比較対象・固有名詞で置き換える。

---

## 2. 定型的な句

記事構造を支えるだけで情報を持たない常套句。

### 動詞を含む定型
- 〜を活用することで
- 〜を利用することで
- 〜を実現することで
- 〜の可能性を秘めている
- 〜の可能性が広がる
- 〜に焦点を当てて
- 〜を紐解いていく
- 〜について解説する / します
- 〜について見ていく / 見ていきましょう
- 〜をご紹介する / します

### まとめ系
- まとめると
- 結論として
- 総じて
- 一言で言えば
- 要するに
- いかがでしたでしょうか

### 呼びかけ系（読者への過剰な配慮）
- ぜひ〜してみてください
- 〜することをおすすめします
- 〜してみましょう
- ぜひ参考にしてみてください

**修正方向**: ほとんど削除して良い。動作主や結果を具体的に書く。

---

## 3. ヘッジ表現

責任回避・断定回避の常套句。多用は避ける。

- 〜かもしれません
- 〜と考えられます
- 〜と思われます
- 〜と言えるでしょう
- 〜と言える
- 〜する可能性がある
- 一般的には
- 傾向がある
- 場合によっては
- ケースバイケース

**修正方向**: 断定できる場合は断定する。本当に不確実なら「自分は〜と思う」「自分の環境では〜だった」と主観を明示する。

---

## 4. 過剰なカタカナ語

日本語で表現できるのにカタカナで置き換えられている場合にフラグ。技術用語として定着しているもの（API、フレームワーク等）は対象外。

### 典型的な過剰カタカナ
- ソリューション → 解決策
- エコシステム → （多くの場合削除可能、または「周辺環境」）
- パラダイムシフト → 根本的な転換
- ゲームチェンジャー → 状況を変えるもの
- シナジー → 相乗効果
- イノベーション → 刷新 / 革新
- コミットメント → 約束 / 責任
- プライオリティ → 優先度
- スケーラビリティ → 拡張性
- フレキシビリティ → 柔軟性

**修正方向**: 技術文脈で定着している語（API, CLI, SDK, SaaS等）は残す。それ以外の抽象的カタカナは日本語に置き換えるか削除する。

---

## 5. 段落末の「きれいに閉じる」系

AIは段落を必ず何らかの締めで終わらせる癖がある。

- 以上が〜です / 以上がポイントです
- 以上のように〜
- このように〜
- 次に進みましょう
- 次は〜について見ていきます
- 最後にまとめます
- 〜していきましょう
- 〜が重要です
- 〜ですね

**修正方向**: 多くの場合、段落末の締め文は削っても意味が通る。削る。特に連続して出現する場合は必ず削る。

---

## 6. 導入の定型

記事や段落の冒頭に置かれる自己言及的な予告。

- 今回は〜について
- 本記事では〜を解説
- この記事では〜を紹介します
- まず〜から見ていきましょう
- ここでは〜について扱います
- 結論から言うと（続く内容が抽象的な場合のみ問題）

**修正方向**: 削除。見出しが十分な予告になっている。本文は即座に本題から始める。

---

## 7. 接続の常套句

### 順接（ほぼ削除可能）
- また
- さらに
- 加えて
- そして
- それに加えて

### 過剰な逆接・転換
- しかしながら（「しかし」で十分）
- 一方で（多用するとAIっぽい）
- とはいえ（多用するとAIっぽい）

### 説明導入
- ここで注目すべきは
- 注目すべき点は
- 特筆すべきは
- 興味深いことに

**修正方向**: 順接は9割削れる。削って文脈で繋がるなら削る。逆接は必要なときだけ使う。

---

## 検出時の注意

- すべての出現を列挙せず、**1記事内で2回以上出る場合**や、**パターンが重なって出る場合**を優先してフラグ
- 技術文書として適切なカタカナ語（API、MCP、CLI等）は検出対象外
- 引用やコード内の文字列は対象外
