# ai-slop-review-ja

日本語文章からAI生成特有のパターン（AI臭・スロップ）を検出する Claude Code プラグイン。

技術記事、ブログ、note、Qiita投稿など、投稿前の日本語文章をレビューし、「誰が読んでもAIっぽいとわかる特徴」を構造化レポートとして指摘します。

## スキル一覧

| スキル | 説明 |
|--------|------|
| `ai-slop-review-ja` | 5レイヤー検出（語彙・文体・構造・コンテンツ・事実性）＋表記所見でAI臭を指摘し、修正方向を示す構造化レポートを出力 |

## 設計思想

このプラグインの責任範囲は「AIっぽく見えない自然な日本語」への修正方向を示すことだけで、特定の執筆者スタイル（一人称、常体/敬体、語彙の好み）への寄せは対象外です。スタイル寄せは別スキルまたは別ターンで行います。

### 誤検出をしないことを優先

人間も「一方で」「まさに」「〜ではなく〜だ」は普通に使います。AIの特徴は個々の表現ではなく、**それを毎回・機械的にやること**にあります。

そのため本スキルは、パターンに一致しただけでは報告しません。**読者にとっての具体的な損失**（重複 / 空洞 / 冗長 / 偽の対比 / 文脈不適合）を説明でき、かつ各パターンの**棄却例**に該当しない場合だけ指摘します。候補を挙げてから反証する2段階の検出フローになっており、迷った指摘は出しません。

### 表記所見は重度判定から分離

見出しのコロン、太字の過剰、絵文字見出しなどは日本語圏で最も「一瞬でAIと分かる」層ですが、内容の質とは独立しています。表記だけ直して「AI臭が消えた」と誤認しないよう、`🖋 表記所見` として重度判定・総合所感から分離しています（表示が壊れる Markdown 記号の残骸のみ例外で最優先）。

### 事実性を最優先

Layer 4 で「具体性を出せ」と指示すると、書き直しエージェントが辻褄合わせで数値・期間・経験を**捏造するリスク**があります。本スキルは捏造リスクのある箇所を `⚠️ 事実性要確認` として明示し、書き直し前に執筆者に確認を求める設計になっています。

## インストール

```bash
# GitHub マーケットプレイスから
/plugin marketplace add naokami3/ai_dotfiles
/plugin install ai-slop-review-ja@ai-dotfiles

# ローカルテスト
claude --plugin-dir ./plugins/ai-slop-review-ja
```

## 使い方

```
/ai-slop-review-ja:ai-slop-review-ja
```

レビュー対象のテキスト（markdown可）を渡すと、以下の形式でレポートが返ります。

- 📊 サマリ（🔴重度 / 🟡中度 / 🟢軽度 / 📐構造的所見 / 🖋表記所見 / ⚠️事実性要確認の件数）
- ⚠️ 事実性要確認（捏造リスクのある具体記述）
- 🔴 / 🟡 / 🟢 各重度の指摘（行番号・引用・問題・**損失**・修正方向）
- 📐 構造的所見（段落長・接続詞頻度・見出し構造）
- 🖋 表記所見（コロン・太字・絵文字見出し・箇条書きの均一性など）
- 🎯 書き直し優先順位

## 検出パターン

| ファイル | 内容 |
|---|---|
| `references/patterns-lexical.md` | Layer 1（語彙）: 定型句、ヘッジ、過剰カタカナ、**否定的対比**、**漢語過剰**、**問いかけ演出** |
| `references/patterns-structural.md` | Layer 2〜5: 文末単調、**抽象名詞の体言止め**、鋳型構造、**三段上昇**、**一点の希釈**、**例外の不在**、事実性 |
| `references/patterns-notation.md` | 表記: コロン、太字過剰、Markdown残骸、絵文字見出し、箇条書きの均一性、em dash |

各パターンには**棄却例**（人間が正当に使う用法）が併記されており、照合してから報告します。
