# claude-dev-orchestration-ja

設計・調査を Opus、実装・テストを Sonnet に分担させる開発オーケストレーション用の Claude Code プラグイン。

「Opus に考えさせて Sonnet に手を動かさせる」という分担を、毎回口頭で指示しなくても再現できるようにします。

## 構成

| 種別 | 名前 | 役割 |
|------|------|------|
| スキル | `design-implement-review` | オーケストレーター（Opus）。調査・設計・ユーザー対話・レビュー結果の集約を担当 |
| エージェント | `impl-worker` (Sonnet) | 作業指示書どおりの実装とテスト実行。レビュー指摘の修正も担当 |
| エージェント | `impl-reviewer` (Sonnet) | 実装が受け入れ基準を満たすかの検証。外部レビュー手段が無い場合のフォールバック |

## ワークフロー

```
Phase 0  モデル確認（Opus でなければユーザーに確認）
Phase 1  調査          ── Opus
Phase 2  設計          ── Opus
Phase 3  承認ゲート    ── ユーザーの承認が必須
Phase 4  実装引き継ぎ  ── Sonnet (impl-worker)
Phase 5  レビュー      ── 外部手段 or Sonnet (impl-reviewer)
Phase 6  修正ループ    ── Sonnet (impl-worker)、最大3周
Phase 7  完了報告      ── Opus
```

## 設計思想

### 承認ゲートを必須にする

Phase 3 でユーザーの承認を得るまで実装フェーズに入りません。Sonnet への引き継ぎは指示書という形で固定されるため、方向がずれたまま実装が走ると手戻りが大きくなります。ずれに気づくコストが最も低いのは設計を提示した直後です。

### 指示書を自己完結させる

サブエージェントは会話履歴を引き継ぎません。Phase 4 で作成する作業指示書は、それ単体で読んで実装できる情報量を持たせます。ゴール、前提知識、変更対象、受け入れ基準、テスト方針、やらないこと、変更してはいけない判断を含めます。

指示書はスクラッチパッドに `<タスク名>-handoff.md` として書き出され、実装エージェントとレビューエージェントの双方が参照します。

### レビューは外部手段を優先する

Phase 5 では、利用可能な外部のレビュー用プラグイン・エージェントを先に探し、あればそれに委譲します。無い場合のみ同梱の `impl-reviewer` を使います。

外部手段とのやりとりは全てオーケストレーター（Opus）が行います。実装エージェントとレビュー担当を直接つながせないことで、実装者の説明がレビューに混入することを防ぎます。

なお、`/code-review` のようなユーザー自身が起動するコマンドはオーケストレーターからは起動できないため、レビュー手段の候補には含めません（ユーザーに使用の意向を尋ねることはあります）。

### 修正ループに上限を置く

Phase 6 は最大3周です。同じ指摘が2周続けて解消しない場合は、実装ではなく設計の問題である可能性が高いため、ループを止めて設計フェーズに戻るかをユーザーに確認します。無限に修正させ続けるより、判断を人間に返すほうが早く終わります。

## インストール

```bash
# GitHub マーケットプレイスから
/plugin marketplace add naokami3/ai_dotfiles
/plugin install claude-dev-orchestration-ja@ai-dotfiles

# ローカルテスト
claude --plugin-dir ./plugins/claude-dev-orchestration-ja
```

## 使い方

Opus のセッションで起動します。

```
/claude-dev-orchestration-ja:design-implement-review
```

「調査して設計してから実装させて」のような依頼でも自動的に起動します。単発の質問や、方針が既に確定している小さな修正には使いません。

## カスタマイズ

### レビュー担当のモデルを変える

`agents/impl-reviewer.md` の frontmatter の `model` を変更します。既定は `sonnet`（テストを実際に実行する確認作業が中心のため）ですが、設計レベルの妥当性まで見せたい場合は `opus` にします。

### 修正ループの上限を変える

`skills/design-implement-review/SKILL.md` の Phase 6 に記載されている周回上限を変更します。
